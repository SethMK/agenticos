### P0-1. SessionStart hook — auto-load CLAUDE.md priorities + verify-log status + current sprint
- **Source:** https://claudefa.st/blog/tools/hooks/session-lifecycle-hooks
- **Rationale (fit=3):** AgenticOS orchestrator (per CLAUDE.md) works story-by-story from PMO kanban; every fresh session re-reads CLAUDE.md + verify-log + tail-of-standups (~5-8k tokens just to get oriented). SessionStart hook pre-injects: (a) tail of `~/Projects/personal/202605_AgenticOS_PMO/ceremonies/sprints/*-current.md`, (b) last 5 lines of `docs/verify-log.md`, (c) any in-progress story IDs.
- **Files to edit:** new `.claude/hooks/sessionstart-context.sh` + `.claude/settings.json` SessionStart matcher.
- **Diff sketch:**
  ```bash
  #!/usr/bin/env bash
  # sessionstart-context.sh
  echo "## Current sprint"
  ls -t ../202605_AgenticOS_PMO/ceremonies/sprints/*.md 2>/dev/null | head -1 | xargs head -30
  echo "## Last verify-log rows"
  tail -5 docs/verify-log.md
  echo "## In-progress stories"
  jq -r '.columns.in_progress[]' ../202605_AgenticOS_PMO/exports/public-board.json
  ```
- **Verification:** new conversation in AgenticOS shows sprint context + verify-log tail as first system reminder; orchestrator skips manual re-grep.
- **Effort:** S · **Reversibility:** trivial.

### P0-2. PostToolUse hook — auto-rebuild data/snapshots/public.json when data/pipeline/ edited

- **Rationale (fit=3):** CLAUDE.md mandates `data/snapshots/public.json` parses with jq before story Done. Pipeline edits today require manual `bun run pipeline` invocation; PostToolUse hook on `data/pipeline/*.ts` write events can re-run pipeline + diff snapshot automatically.
- **Files to edit:** new `.claude/hooks/post-pipeline-edit.sh` + `.claude/settings.local.json` (new) — PostToolUse on Edit|Write of `data/pipeline/*.ts`.
- **Diff sketch:**

  ```bash
  CLAUDE_TOOL_INPUT=$1
  if [[ "$CLAUDE_TOOL_INPUT" == *"data/pipeline/"* ]]; then
    bun run pipeline:rebuild > /tmp/agenticos-pipeline.log 2>&1
    jq -e '.totals' data/snapshots/public.json > /dev/null || echo "WARN: public.json malformed"
  fi
  ```
- **Verification:** edit `data/pipeline/aggregate.ts` → public.json mtime updates within 5s + jq parses cleanly.
- **Effort:** S · **Reversibility:** trivial.

### P0-3. qa-verifier token self-report enforcement — Stop hook check
- **Source:** PMO CLAUDE.md SPR-011 retro #2 (cross-window handoff QA mandate) · https://github.com/anthropics/claude-code/releases/tag/v2.1.145 (`claude agents --json`)
- **Rationale (fit=3):** PMO mandates cross-window stories report `implementer total_tokens_k: X · QA total_tokens_k: Y · wall_min: Z` in done-message. AgenticOS has no enforcement → SPR-011 S091 shipped with QA `total_tokens_k: 0` (silent regression). A Stop hook can grep the last assistant turn for the report format, soft-block (continueOnBlock) if missing.
- **Files to edit:** new `.claude/hooks/stop-qa-token-check.sh` + settings entry.
- **Diff sketch:**
  ```bash
  LAST_TURN=$(cat $CLAUDE_TRANSCRIPT | tail -200)
  if echo "$LAST_TURN" | grep -q "cross-window" && ! echo "$LAST_TURN" | grep -qE "implementer total_tokens_k: [0-9]+ · QA total_tokens_k: [0-9]+"; then
    echo '{"continue": false, "reason": "cross-window story Done message missing token self-report (PMO CLAUDE.md SPR-011 mandate)"}' | tee >&2
    exit 2
  fi
  ```
- **Verification:** mark cross-window story Done WITHOUT token-self-report → hook blocks turn end + injects rule citation.
- **Effort:** S · **Reversibility:** trivial · **Dependency:** Claude Code ≥ v2.1.139 (continueOnBlock support).

## Setup gap notes (greenfield baseline)

The minimal `.claude/` setup means several structural gaps exist BEYOND what the research surfaced. Calling out for next-cycle attention:

1. **No `.claude/settings.local.json`** — all permissions inherited from global. AgenticOS-specific permission grants (bun, jq, rsync, ssh to LXC) probably belong in project-local config once deploy phase ramps.
2. **No project-scoped commands** — `/verify`, `/snapshot-rebuild`, `/deploy` would all benefit from existence.
3. **No project-scoped skills** — agents currently rely on global (frontend-design, huashu-design). At least one AgenticOS-scoped skill (`pipeline-rebuild`, `snapshot-validate`, `verify-story`) would reduce orchestrator burden.
4. **No agent for cross-window orchestration** — AgenticOS implementer agents work on AgenticOS-side stories, but the cross-window-handoff coordinator role (per PMO CLAUDE.md SPR-011 mandate) has no dedicated agent. A `handoff-coordinator` agent that owns the token-self-report compliance + verify-log row appending would close the silent-regression gap structurally.
