## P0 — Adopt this cycle

### P0-1 · Enable the `security-guidance` plugin
- **Fit: 3** · already-in-use: no · effort: **XS** (enable plugin) · reversible: **trivial** · deps: plugin install · CLAUDE.md: pass
- **What it is:** Anthropic's free, zero-config plugin (public launch 2026-05-27). Deterministic **no-model** pattern-match on every file edit (flags `eval()`, `os.system()`, `child_process.exec()`, pickle, DOM-injection), a full-diff review per session, and a deep review on commit/push. Anthropic's internal testing cut security-related PR comments **30–40%**.
- **Why P0 for AgenticOS specifically:** the public site is internet-facing, runs a Bun API with an auth header guard, ships a `data/redaction-map.json` (real project names must never leak), and uses Cloudflare Access. Sub-agents author backend + frontend code unattended. A deterministic guardrail on every edit + commit is high-value here (and PMO's own cache already flagged this "P0 for AgenticOS").
- **Files to edit:** none in-repo — enable via `enabledPlugins` (global `~/.claude/settings.json`) or `claude plugin enable security-guidance`. Optionally pin in a project marketplace entry so it travels with the repo.
- **Diff sketch:**
  ```json
  // ~/.claude/settings.json  → enabledPlugins
  "security-guidance@claude-plugins-official": true
  ```
- **Verify:** make a throwaway edit introducing `child_process.exec(userInput)` in a `.ts` scratch file → plugin flags it inline before the edit completes; remove scratch file.
- Sources: https://code.claude.com/docs/en/security-guidance · https://www.helpnetsecurity.com/2026/05/27/anthropic-claude-code-security-guidance-plugin/

### P1-1 · Dynamic Workflows — spike for codebase audits / migrations (with a hard budget gate)
- **Fit: 3** · already-in-use: no · effort: M · reversible: trivial · CLAUDE.md: pass
- **What it is:** Claude writes a JS orchestration script on the fly and fans work across many parallel subagents (16 concurrent / 1,000 total cap) that adversarially cross-check before converging. Built for codebase-wide audits + large migrations — exactly AgenticOS-shaped work (the launch demo was a 750k-LOC Bun Zig→Rust port with two-reviewers-per-file). Invoked by asking for "a workflow" or via the `ultracode` effort setting.
- **Cost caveat (the gating concern):** community reports (Latent Space + walkthroughs) flag severe token blow-up, an "efficiency paradox" (faster to mediocre, not consistently better), and a parallel-edit synchronization risk. **Gate adoption on a scoped spike.**
- **Files to edit:** none yet — spike on a bounded task (e.g. "audit every Astro component for unredacted real-project-name leakage against `data/redaction-map.json`"), which is naturally fan-out-shaped and read-only (no parallel-edit conflict).
- **Verify:** spike produces the audit + a recorded token cost; adopt only for read-heavy audits where parallel verification pays for itself.
- Sources: https://claude.com/blog/introducing-dynamic-workflows-in-claude-code · https://www.youtube.com/watch?v=iJHJaTOwggs · https://www.latent.space/p/ainews-anthropic-raises-965b-series
